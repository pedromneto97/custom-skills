# SeaORM 2.x — Migrations

> Schema-first workflow. For entity-first (generate schema from entities) see `13-entity-first.md`.

## Install CLI
```shell
# Open-source
cargo install sea-orm-cli@^2.0

# SeaORM-X (from local path after cloning sea-orm-x)
cargo install --path "<SEA_ORM_X_ROOT>/sea-orm-x/sea-orm-cli"
```

## Init the migration crate
```shell
sea-orm-cli migrate init                      # creates ./migration
sea-orm-cli migrate init -d ./db/migration    # custom location
```

migration/

Some workspaces name this crate `migrations/` instead of `migration/`. Both are valid.

## Naming conventions

Use timestamp + action naming to keep history readable and deterministic:

```text
m20260412_150756_add_user_profile_name.rs
m20260420_090000_create_orders_table.rs
m20260421_101500_add_unique_index_orders_reference.rs
```

Prefer explicit names for indexes and foreign keys so production errors are easier to trace.

## `migration/Cargo.toml`
```toml
[dependencies]
tokio = { version = "1", features = ["macros", "rt-multi-thread"] }

[dependencies.sea-orm-migration]
version = "2.0"
features = [
  # Needed to run migrations via the CLI / main.rs. Match the main crate.
  "runtime-tokio-rustls",
  "sqlx-postgres",        # or sqlx-mysql / sqlx-sqlite; SeaORM-X: "sqlz-mssql"
]
```

> SeaORM-X (MSSQL): the migration crate comes from the same git repo / path as `sea-orm`
> (`01-cargo-setup.md`) and must enable `sqlz-mssql`, or `sea-orm-cli migrate -u mssql://…`
> runs a migrator without an MSSQL driver.

## Migration file template
```rust
// migration/src/m20220101_000001_create_table.rs
use sea_orm_migration::{prelude::*, schema::*};

#[derive(DeriveMigrationName)]
pub struct Migration;

#[async_trait::async_trait]
impl MigrationTrait for Migration {
    async fn up(&self, manager: &SchemaManager) -> Result<(), DbErr> {
        manager
            .create_table(
                Table::create()
                    .table(Post::Table)
                    .if_not_exists()
                    .col(pk_auto(Post::Id))         // Postgres: GENERATED BY DEFAULT AS IDENTITY
                    .col(string(Post::Title))
                    .col(string_null(Post::Body))
                    .to_owned(),
            )
            .await?;

        manager
            .create_index(
                Index::create()
                    .if_not_exists()
                    .name("idx-post-title")
                    .table(Post::Table)
                    .col(Post::Title)
                    .to_owned(),
            )
            .await?;

        Ok(())
    }

    async fn down(&self, manager: &SchemaManager) -> Result<(), DbErr> {
        manager.drop_index(Index::drop().name("idx-post-title").table(Post::Table).to_owned()).await?;
        manager.drop_table(Table::drop().table(Post::Table).to_owned()).await?;
        Ok(())
    }
}

#[derive(DeriveIden)]
enum Post {
    Table,
    Id,
    Title,
    Body,
}
```

> `#[async_trait::async_trait]` is the form the CLI template uses (the prelude re-exports the
> `async_trait` crate, not the bare attribute). Table/column names may also be plain strings
> (`.table("post")`, `pk_auto("id")`) instead of a `DeriveIden` enum.

## Transactions per migration
Default: Postgres wraps **each** migration in a transaction; MySQL and SQLite do not (MySQL DDL
auto-commits anyway). Override per migration:

```rust
#[async_trait::async_trait]
impl MigrationTrait for Migration {
    // None = backend default, Some(true) = force txn, Some(false) = no txn
    fn use_transaction(&self) -> Option<bool> { Some(false) }

    async fn up(&self, manager: &SchemaManager) -> Result<(), DbErr> {
        let m = manager.begin().await?;           // manual txn for part of the work
        m.create_table(/* ... */).await?;
        m.commit().await?;

        // Must run outside a transaction on Postgres
        manager.get_connection()
            .execute_unprepared("CREATE INDEX CONCURRENTLY idx_name ON my_table (name)")
            .await?;
        Ok(())
    }
}
```

## Schema helper functions (`schema::*`)
```rust
pk_auto(col)                     // PK + auto-increment (IDENTITY on Postgres 2.0 / MSSQL)
pk_uuid(col)                     // UUID PK
big_integer(col)                 // BIGINT
big_integer_null(col)            // nullable BIGINT
string(col)                      // VARCHAR(255) / nvarchar(255) on MSSQL
string_null(col)                 // nullable VARCHAR(255)
string_len(col, 100)             // VARCHAR(100)
string_len_null(col, 100)        // nullable VARCHAR(100)
string_uniq(col)                 // VARCHAR(255) UNIQUE
string_len_uniq(col, 320)        // VARCHAR(320) UNIQUE
integer(col)                     // INT
integer_null(col)                // nullable INT
boolean(col)                     // BOOLEAN / TINYINT(1)
timestamp(col)                   // TIMESTAMP (without time zone)
timestamp_with_time_zone(col)    // TIMESTAMPTZ
timestamp_default_now(col)       // TIMESTAMP DEFAULT CURRENT_TIMESTAMP (also date_time_default_now,
                                 //   timestamp_with_time_zone_default_now)
uuid(col)                        // UUID
json_binary(col)                 // JSONB

// ENUM column (name, enum type, variants)
enumeration(col, "role", ["owner", "admin", "operator"])
enumeration_null(col, "role", ["owner", "admin", "operator"])

// Default value
string(Users::Name).default(Expr::value("anonymous"))
timestamp(Orders::CreatedAt).default(Expr::current_timestamp())
boolean(Stores::Active).default(Expr::value(true))
```

> Postgres 2.0: `pk_auto` / auto-increment emits `GENERATED BY DEFAULT AS IDENTITY` instead of
> `serial`. Enable feature `postgres-use-serial-pk` to keep v1 behavior.

### Named foreign keys and indexes (recommended — aids debugging)

```rust
ForeignKey::create()
    .name("fk-order_items-order_id")
    .from(OrderItems::Table, OrderItems::OrderId)
    .to(Orders::Table, Orders::Id)
    .on_delete(ForeignKeyAction::Cascade)
    .to_owned()

Index::create()
    .name("idx-store_users-store_id-user_id")
    .table(StoreUsers::Table)
    .col(StoreUsers::StoreId)
    .col(StoreUsers::UserId)
    .unique()
    .if_not_exists()
    .to_owned()
```

For teams that standardize names, these prefixes are common:
- `pk-...` primary keys
- `fk-...` foreign keys
- `idx-...` non-unique indexes
- `uq-...` unique indexes/constraints

## SchemaManager DDL API
```rust
manager.create_table(..)       manager.drop_table(..)
manager.alter_table(..)        manager.rename_table(..)
manager.truncate_table(..)
manager.create_index(..)       manager.drop_index(..)
manager.create_foreign_key(..) manager.drop_foreign_key(..)

// Postgres only — native ENUM types
manager.create_type(..)  manager.alter_type(..)  manager.drop_type(..)

// Inspection
manager.has_table("orders").await?
manager.has_column("orders", "status").await?
manager.has_index("orders", "idx-orders-status").await?
```

### Postgres ENUM type
```rust
use sea_orm_migration::sea_query::extension::postgres::Type;

manager
    .create_type(
        Type::create()
            .as_enum("role")
            .values(["owner", "admin", "operator"])
            .to_owned(),
    )
    .await?;
// down: manager.drop_type(Type::drop().name("role").to_owned()).await?;
```

## Raw SQL in migrations
```rust
let db = manager.get_connection();

// DDL / no bindings
db.execute_unprepared("CREATE TABLE ...").await?;

// With values (v2: raw Statement goes to *_raw methods)
use sea_orm_migration::sea_orm::Statement;
db.execute_raw(Statement::from_sql_and_values(
    manager.get_database_backend(),
    r#"INSERT INTO "cake" ("name") VALUES ($1)"#,
    ["Cheese Cake".into()],
)).await?;
```

## Seed data inside a migration
```rust
cake::ActiveModel { name: Set("Cheesecake".to_owned()), ..Default::default() }
    .insert(manager.get_connection())
    .await?;
```

## Create tables from entities inside a migration
No extra feature needed for `apply` (only `.sync` needs `schema-sync`). Useful when entities are the source of truth:
```rust
async fn up(&self, manager: &SchemaManager) -> Result<(), DbErr> {
    let db = manager.get_connection();
    db.get_schema_builder()
        .register(cake::Entity)
        .register(fruit::Entity)
        .apply(db)          // create in FK order (use .sync(db) to diff existing schema)
        .await
}
```

## CLI commands
`DATABASE_URL` (env or `.env`) or `-u` must be set.

```shell
sea-orm-cli migrate init                  # create migration crate
sea-orm-cli migrate generate create_post  # new migration file (add --local-time for local tz)
sea-orm-cli migrate up                    # apply all pending
sea-orm-cli migrate up -n 10              # apply 10 pending
sea-orm-cli migrate down                  # roll back last one
sea-orm-cli migrate down -n 3             # roll back 3
sea-orm-cli migrate status
sea-orm-cli migrate fresh                 # DROP all tables, then apply all
sea-orm-cli migrate refresh               # roll back all, then apply all
sea-orm-cli migrate reset                 # roll back all

# Other migration dir
sea-orm-cli migrate up -d ./db/migration

# Override URL
sea-orm-cli migrate up -u postgres://user:pass@localhost/db

# Non-default schema (Postgres / MSSQL)
sea-orm-cli migrate up -u "postgres://user:pass@localhost/db" -s my_schema
sea-orm-cli migrate up -u "mssql://sa:pass@localhost/db" -s my_schema
```

`sea-orm-cli migrate X` = `cargo run --manifest-path ./migration/Cargo.toml -- X`, so
`cd migration && cargo run -- up` also works.

## Run programmatically
```rust
use migration::{Migrator, MigratorTrait};

let db = Database::connect(&database_url).await?;
Migrator::up(&db, None).await?;            // all pending (Some(n) for n)
// Migrator::down(&db, Some(1)).await?;
// Migrator::status(&db).await?;
// Migrator::fresh(&db).await?; Migrator::refresh(&db).await?; Migrator::reset(&db).await?;

let pending = Migrator::get_pending_migrations(&db).await?;
let applied = Migrator::get_applied_migrations(&db).await?;
// *_read_only variants (2.0.1+) don't create the seaql_migrations table — use for health checks
let pending = Migrator::get_pending_migrations_read_only(&db).await?;
```
